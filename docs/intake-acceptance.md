# 录入模块 1.1–1.10 验收范围

## 已实现的代码流程
- AI 对话与手动录入统一入口；AI 意图仅建议、人工确认才启动提取。
- 原文、原文件、来源资料与录入任务追溯；批次可复用来源。
- TXT/LaTeX/Markdown/CSV、DOCX 正文与部分公式、PDF 文字层、可选本地 OCR。
- 结构化草稿，AI 补充按字段采纳，Word 结构化编辑与引用。
- Word AI 修改建议按字段和版本确认；不修改已有引用。
- 全库规范化题干/完全重复索引，近期相似候选，知识点名称/别名匹配。
- 每批 20 个待入库条目，选择新建/复用/追加解法；失败整批回滚。
- 保存入库前草稿、资源前后快照、来源及关联知识点 ID。

## 自动化验证
CI 的 Python 3.10/3.12 PostgreSQL 集成测试覆盖来源复用、导入、聊天来源、AI 提取/补充、文档生成、Word AI 编辑、入库历史、重复解析追加及批量回滚。Qoder 使用隔离的模拟响应。浏览器使用编译后的 React 应用及隔离 API 夹具；不代表生产真实模型的数学输出。以对应提交的 GitHub Actions 结果为准，不在仓库中静态宣称通过。

## 生产验收（需真实服务）
1. 先核对部署版本、/api/health、/api/ready，以及 Qoder 授权状态。
2. 检查本地 pdftotext、pdftoppm、prlimit、tesseract 及 chi_sim、eng 语言库；缺失则由服务器管理员安装 poppler-utils、tesseract-ocr、tesseract-ocr-chi-sim、tesseract-ocr-eng。
3. 用人工确认的小型样本逐类导入：纯文本、LaTeX、DOCX、文字版 PDF、扫描 PDF、图片。比较原件与提取文本，核对公式、图形、表格与题号。
4. 使用真实 Qoder 做一次提取、补充、Word 指令编辑；测试失败/取消以及版本冲突，不自动接受模型建议。
5. 在专用测试来源与测试文档中，检查完全重复、同题不同解析、答案冲突，确认批量入库及回滚；在历史面板复查原文。避免污染正式题库。
6. 核对新资源的题库详情、来源、知识点、LaTeX 排版、视频制作入口；测试手机与桌面。

## 限制
规范化题干相同只是候选，不证明数学等价；相似检索仅近期 300 条且截断文本，需人工确认。名称/别名匹配可能漏检；没有自动语义分类。OCR 与复杂 Word 公式/图形须人工核对。历史记录不等于自动撤销；旧版单条 register 接口保留兼容。生产真实模型、OCR 与真实视频出片均需单独验收。
